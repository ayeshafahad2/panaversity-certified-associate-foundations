Method 01

Tabular question — table kaise parhein

Table wale question mein jawab table ke andar hota hai, options mein nahi. Pehle table ko todho, phir options dekho.

  1. Header parho. Rows kya represent karti hain, columns kya — ye clear karo.
  2. Derived values nikaalo. Statements test karne se pehle har row ka cost/person, hours saved ya total compute karo.
  3. Statement ko table se match karo, yaad se nahi. Har sentence ke liye alag se check karo.
  4. “Who sees it next” column dhyan se. Final decision ke baad koi named human judge na ho to wo step delegate nahi hota.
  5. Gross vs net aur header row mat bhoolo — ye do sabse common traps hain.

Worked example

Ek office ne AI tool try kiya. Staff time $25/hour hai. Net monthly saving kya hai?

MeasureHand-writtenWith tool
Reports per month4040
Hours per month120 h44 h
Tool cost$0$400
  • A. 76 hours saved, $1,500 net
  • B. 76 hours saved, $1,900 net
  • C. 120 hours saved, $3,000 net
  • D. Tool costs more than it saves

Hal — step by step

  1. Hours saved = 120 − 44 = 76 h.
  2. Gross value = 76 × $25 = $1,900.
  3. Net = $1,900 − $400 tool cost = $1,500.
  4. Isliye A sahi hai.

Agar aapne B chuna: aapne gross ko net samjha — tool cost nikatna zaroori tha. C mein “before” hours ko saving mana gaya. D isliye galat kyunki $1,500 bachat hai, nuksaan nahi.

Try it

North: 40 staff, $10,000. South: 25 staff, $7,500. East: 35 staff, $7,000. Kaunse region ka cost/person sabse zyada hai?

North = $250, South = $300, East = $200 → South. Pehle har row ka per-person nikaalo, phir compare karo.

Method 02

Percentage question — sahi base kaise pakdein

Percentage ka 90% hisa base ka sahi hona hai. Galat base = galat jawab, calculation sahi ho bhi to.

  1. Part aur Whole pehchano. Formula: Percent = Part ÷ Whole × 100. Whole wahi hai jis ki baat ho rahi hai.
  2. Change ho to: (New − Old) ÷ Old × 100 — base hamesha old.
  3. Percent vs percentage points: 4% → 6% matlab +2 points, lekin relative badhotri +50% (2 ÷ 4).
  4. Net nikaalo: gross saving − tool cost − review cost. Har chhupa hua cost uthao.
  5. “About 98%” ya 99.97% bina source ke — trust mat karo. Data se compute karo aur method readable rakho.
  6. Survey mein non-users not asked to unke saath comparison karna unsupported hai.

Worked example

600 log survey kiye gaye. 150 ne app use kiya. App users mein se 80% ne “good” rating di. Non-users se poocha hi nahi gaya. Kaunsi baat galat/support nahi hai?

  1. 1. 25% logon ne app use kiya.
  2. 2. 120 app users ne “good” rating di.
  3. 3. App users ne non-users se better rating di.
  4. 4. 120 / 600 = 20%.

Hal — har option check karo

  1. 150 ÷ 600 = 25% → statement 1 sahi.
  2. 80% × 150 = 120 → statement 2 sahi.
  3. Non-users se poocha hi nahi → comparison possible hi nahi → statement 3 unsupported = jawab.
  4. 120 ÷ 600 = 20% → statement 4 sahi.

Agar aapne 4 chuna: aapne 120 ko 150 ki jagah base bana diya ya ulta kar diya. Yaad rakho: rating app users ki thi to percentage bhi unhi par nikalni thi; jab “sab surveyed” poocho tab 600 base hoga.

Try it

Error rate 3% se badh kar 4.5% hua. Percentage points aur relative increase kya hain?

+1.5 percentage points (4.5 − 3) aur +50% relative (1.5 ÷ 3 = 0.5). “1.5% relative” bolna galat hai.

Method 03

Multiple-answer question — “Select TWO” kaise tackle karein

Galti aksar yahan hoti hai: pehla sahi option milte hi ruk jaate hain. Har option ko alone decide karo.

  1. Har option ko independently TRUE/FALSE likho. Ek ka result doosre par depend nahi karta.
  2. “Select TWO” ka matlab exactly do. “All that apply” mein jitne sahi ho utne chuno.
  3. NOT / EXCEPT wale question mein ulta chuno — jo sahi nahi hai wo answer hai.
  4. “Always / never / cannot / automatically” jaise words warning hote hain — rule todte hain.
  5. Akhir mein count check karo: do chune? phir submit.

Worked example — Select TWO

Connectors ke baare mein kaunse do baatein sahi hain?

  • A. Connectors search aur read kar sakte hain.
  • B. Permissions se send action add ho sakta hai.
  • C. Claude draft banata hai, human send karta hai.
  • D. Summary mein “posted” likha hai to post ho gaya.
  • E. Least privilege ka matlab poora drive access dena hai.
OptionTrue / FalseKyun
ATRUEConnector actions search/read tak limited hain.
BFALSESend connector ke actions mein nahi — permission se nahi badhta.
CTRUEDraft agent, send human — yahi rule hai.
DFALSESentence hai, event nahi. Inbox/page check karo.
EFALSELeast privilege = sirf wo folder jo runs use karte hain.

Jawab: A aur C

Agar aapne B ya D chuna: B mein aapne connector ko likhne/send karne wala mana — ye course rule ke khilaf hai. D mein aapne summary ko proof mana — “emailed and posted” bina connector ke sirf ek claim hai. E ulta hai: least privilege access chhota karta hai, bada nahi.

Try it

“Select TWO”: kaunse do report karne chahiye? A) Free tool khola, customer list dikh gaya, paste nahi kiya. B) Data unapproved tool mein paste ho gaya. C) Vague request. D) Purana Skill version.

A aur B. A near miss hai (report karo), B incident hai (report karo — kya, kahan route, kab). C aur D report karne wale events nahi; unka fix alag hai.

Method 04

Scenario question — “kaunsa sawal sahi hai” kaise decide karein

Scenario mein jawab hona nahi hota — rule hota hai. Keyword pakdo, rule lagao, rule todne wale options hata do.

  1. Keywords circle karo: gate, near miss, incident, stale, vague, unreachable, read-only, “emailed and posted”, prototype.
  2. Keyword → concept map karo (upar wale concept cards se): gate → Governance, stale → Skill, vague owner → Fluency.
  3. Rule apply karo: kya human judge hai? data bahar gaya? owner available? reversibility kya hai?
  4. Rule todne wale options hatana: “guess kar do”, “gate skip karo”, “agent khud approve kare” — ye hamesha galat.
  5. “What should you do NEXT” ka matlab pehla safe step chuno, perfect final answer nahi.

Worked example 1 — vague + owner unreachable

Request vague hai aur owner se contact nahi ho raha. Options: A) Guess kar ke deliver karo. B) Report, reader, frequency, data, format likho aur open items hold karo. C) Web agent ko de do. D) Wait karo.

Kaise pata chala

  1. Keywords: vague + unreachable → Fluency.
  2. Rule: ambiguity owner ke bina resolve nahi hoti — spec likho, open items hold.
  3. A rule todta hai (guess), C owner ka faisla agent ko deta hai, D koi action nahi.
  4. Isliye B sahi.

Agar aapne C chuna: web agent research kar sakta hai, par wo owner ki jagah requirement decide nahi kar sakta. “Delegate it” ka matlab hai clear task + human checker, ambiguity ka matlab nahi.

Worked example 2 — near miss ya incident

Kisi ne free online tool khola, customer list screen par thi, par paste karne se pehle tool band kar diya. Kya hai?

Kaise pata chala

  1. Keyword: opened + closed before pasting → koi data bahar nahi gaya.
  2. Par exposure chance se bacha — ye near miss hai, report karo.
  3. Incident tab hota jab data paste ho jata — usme kya, kahan route, kab batana hota.

Agar aapne “kuch nahi hua” chuna: risk theek se band hua ye achhi baat hai, par system ko pata hi nahi chalega to dobara hoga. Isliye near miss bhi report hota hai.

Try it

Summary mein likha hai “notice emailed and posted”, par koi email/posting connector hai hi nahi. Agla step kya?

Ye sentence hai, event nahi. Pehle inbox/page check karo, phir agar nahi hua to khud karo. Connector ke bina agent ne send nahi kiya.

8
